# ساسكي → لوفي: معاينة صلاحيات التعيين (10-30)

الفرع `avg-sasuke` مدموج وياه avg `f8e47c8c` (يشمل `53e045d0` و`headPermissions`). تغييرات الباك إند الداخلة بالدمج هي شغلكم مثل ما هي؛ ساسكي ما غيّر الباك إند أو الترحيلات.

## الجاهز

- بنافذة «تعيين بالهيكل» من الشجرة أو ترتيب الموظفين، قسم «🔑 الصلاحيات الي راح ياخذها» قبل حفظ التعيين. يتحدث فوراً عند تغيير الإدارة أو الوحدة أو المنصب، مع المكان والمنصب والعدد الحقيقي للصلاحيات الفريدة.
- العضو بوحدة: `unit.permissions` ناقص `unit.headPermissions`. رئيس الوحدة ونائبه: الحزمة كاملة.
- عضو إدارة بلا وحدة: `division.permissions` ناقص `division.headPermissions`. مدير الإدارة ونائبه: حزمة الإدارة واتحاد حزم وحداتها كاملة، بلا تكرار، مرتبة باسم الصلاحية الأصلي مثل العقد.
- الحالة الصفرية واضحة: «هالمنصب بهالمكان ما يضيف أي صلاحية». لا صلاحيات متخيّلة لعضو الإدارة أو حزمة فارغة، ولا قائمة ثابتة بالواجهة.
- الأسماء العربية من catalog المحمّل أصلاً. الرمز غير المعروف يظهر صريحاً، وفشل catalog يعرض تنبيهاً ورموز الصلاحيات بدل التخمين. إذا بيانات `headPermissions` ناقصة عند العضو، يظهر تعذّر المعاينة وليس كل الحزمة أو صفر كاذب. هذا تنبيه بالمعاينة، وليس تغييراً لصلاحية التعيين بالخادم أو منعاً جديداً للحفظ.
- تنبيه دائم: المعاينة لهالتعيين فقط، مو كل صلاحيات الموظف؛ الصلاحيات اليدوية تبقى والدور القديم ما يتغيّر. لا استعلام عن صلاحيات الموظف ولا كتابة/إلغاء صلاحيات من المعاينة.
- إعادة استخدام chart وcatalog من شاشة الهيكل، بلا أي API إضافي أو طلبات لغير الأدمن والمالك. مسار وجسم حفظ التعيين نفس السابق، بلا قائمة permissions يرسلها العميل. لا `prompt` ولا `confirm`.
- نفس ألوان النظام ومتغيراته نهاري/ليلي، RTL، وقائمة طويلة بتمرير داخل المعاينة حتى تبقى النافذة قابلة للاستخدام.

## الفحوص

نجحت `tsc` و`eslint` و`build`. توسّع `scripts/check-org-ui.cjs` لاختبار كل حالات الجدول: عضو/مدير/نائب الوحدة والإدارة، استبعاد headOnly، اتحاد أكثر من وحدة وحذف التكرار، الإدارات والحزم الفارغة، تبديل المكان وإفراغ الوحدة، نقص headPermissions وفشل catalog، وعدم إرسال أي API أو كتابة أثناء تغيير المعاينة. اختبارات الحفظ والخطأ 409 والمخصص وإنهاء المنصب القديمة باقية. الموظف العادي صفر طلب chart أو تعيين. فحص 390/1366 ونهاري/ليلي، تباين ملاحظة المعاينة ≥4.5:1، وعدم تجاوز العرض.

نجحت كذلك فحوص عدم التراجع `check-org-desk.cjs` و`check-org-outputs.cjs`. الفحص Chromium مع APIs مصطنعة، مو إنتاج أو آيفون حقيقي. يبقى الفحص الحي من لوفي/ناروتو لمطابقة حزم القاعدة الفعلية وما يحتفظ به الموظف يدوياً. ماكو نشر برود؛ يلزم الدمج والنشر وبناء الواجهة على السيرفر.
