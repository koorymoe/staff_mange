# قرار (ع): مكتبة 100 شخصية والمالك يختار ويسمّي

هذا القرار يلغي شرط «توليد وجه مطابق تلقائياً من صورة كل موظف» كمسار البداية.
المنتج المطلوب الآن **مكتبة مغلقة من 100 شخصية جاهزة** بنفس الستايل البصري
المعتمد، والمالك يختار الأقرب لكل موظف ويسمّيها قبل أن تظهر في حسابه.

## 1. تجربة المالك

1. يفتح شاشة **مكتبة الشخصيات**.
2. يرى 100 بطاقة مع preview والسمات.
3. يبحث ويصفي: رجل/امرأة، لحية/بدون، لون البشرة، الشعر، النظارة، والسمات.
4. يختار شخصية قريبة من الموظف ويشاهدها بالحجم الحقيقي داخل النظام.
5. يكتب **اسم الشخصية** الذي يريد ظهوره للموظف.
6. يختار الموظف ويضغط «تعيين».
7. الخادم يحفظ التعيين، فتظهر الشخصية واسمها بحساب الموظف.
8. تغييرها لاحقاً لا يمسح تاريخ القصص أو العقوبات أو الإقرارات.

الاختيار والتسمية والتعيين **للمالك فقط** في البداية. الموظف لا يبدلها بنفسه.

## 2. معنى «واحد خاص بكل موظف»

- كل موظف عنده assignment فعال واحد.
- الـpreset المختار والاسم مرتبطان بملف الموظف.
- نسجل من عيّنها ومتى.
- اقتراح (م): نسمح تقنياً باستعمال preset لأكثر من موظف، لكن نظهر للمالك
  «مستخدمة» حتى يقدر يجعل كل موظف مميزاً. (ع) يحسم إذا يريد منع التكرار.

## 3. الهوية البصرية الثابتة

- 3D animated-film mascot، مو vector مسطح.
- الرأس 38–42% من طول الشخصية، والجسم قصير وممتلئ وأطرافه قصيرة.
- مظهر بالغ وودود، عيون كبيرة، شعر ووجه مفصلان.
- سترة الأماني الزرقاء؛ ما تحتها أسود فقط.
- نفس الإضاءة والخامة وزاوية الوقوف والجودة لكل المكتبة.
- الاختلاف بالوجه والشعر واللحية/الشارب والنظارة ولون البشرة والسمات، لا بالزي.

## 4. توزيع الـ100 قبل التوليد

نستعمل matrix مقصودة بدل 100 صورة عشوائية:

- 60 شخصية رجال: 30 بلحية/شارب بدرجات، و30 بدون لحية.
- 40 شخصية نساء: تنوع وجوه وشعر، ومع خيارات حجاب إذا أكدها (ع).
- خمس درجات بشرة موزعة على الجنسين بلا ربطها بتسريحة أو سمة واحدة.
- شعر قصير/متوسط/طويل، مستقيم/مموج/مجعد، وأسود/بني/داكن/رمادي مناسب للعمر.
- أشكال وجه: بيضاوي، دائري، مربع، طويل، وفك واضح.
- فئات عمر بصري بالغ: شاب، متوسط، أكبر؛ لا شخصيات أطفال.
- نظارات بعدد محدود، وبدون إكسسوارات تغيّر هوية شركة الأماني.

كل شخصية تحمل code ثابتاً `AV001` إلى `AV100`. الاسم الذي يكتبه المالك منفصل
عن الكود؛ تغيير الاسم لا يغير asset ولا يكسر القصص.

## 5. البيانات المقترحة — راجعها (ز) مقابل الموجود

لا ننشئها قبل مراجعة `EmployeeCharacter` الموجود:

```ts
type AvatarPreset = {
  code: string              // AV001..AV100
  version: number
  presentation: 'MALE' | 'FEMALE'
  skinTone: string
  hairStyle: string
  hairColor: string
  facialHair: string
  glasses: boolean
  tags: string[]
  previewKey: string
  rigProfile: string
  active: boolean
}

type EmployeeAvatarAssignment = {
  employeeId: string
  presetCode: string
  characterName: string
  assignedByEmployeeId: string
  assignedAt: string
}
```

الـpreviewKey مفتاح تخزين، لا base64 داخل القاعدة. الـrigProfile يحدد مجموعة
الطبقات/الحركة المشتركة، وليس ملف Rive جديداً لكل شخصية.

## 6. الحركة بدون 100 Rig

لا نبني 100 منظومة عظام. نبني **Rig مشتركاً** للرجل وRig مشتركاً للمرأة (أو
نثبت بالتجربة إمكان Rig واحد)، ثم نبدل طبقات المظهر. القصص والأفعال واحدة:
idle/blink/look/talk/walk/run/receive/carry/deliver/read/point.

إذا بقي المسار SVG:
- لكل preset appearance parts أو sprite layers متوافقة مع نفس anchors.
- محرك الحركة يطبق transforms نفسها على الجميع.

إذا فتحنا Rive لاحقاً:
- نفس presets تُربط بالـslots/data binding.
- لا ملف `.riv` مستقل لكل موظف ولا لكل preset.

## 7. خطة إنتاج لا تهدر الوقت

1. نثبت **شخصيتين Golden Samples**: رجل من صورة الموظف الحالية، وامرأة يختار
   (ع) مرجعها.
2. نفصل ونحرك العين/الرمش/الفم/الرأس/اليدين في نموذج القصة.
3. إذا نجحت الجودة بالحجم الحقيقي، ننتج دفعات 10 شخصيات.
4. (ع) يراجع كل دفعة؛ المرفوضة تعاد قبل توليد الدفعة التالية.
5. بعد اعتماد 100، نبني شاشة المكتبة والتصفية والتسمية والتعيين.

إنتاج 100 دفعة واحدة قبل تثبيت Golden Samples يكرر الخطأ 100 مرة؛ لذلك
الاعتماد يكون 2 ← 10 ← 25 ← 50 ← 100.

## 8. أسئلة الحسم إلى (ز)

1. هل نوسع `EmployeeCharacter` الموجود بـ`presetCode` و`characterName` وبيانات
   التعيين، أم الموجود يحتاج كيان catalog مستقل + FK؟
2. أين نخزن manifest الـ100 حتى يكون مصدر حقيقة واحداً: جدول seed أم ملف JSON؟
3. ما أقل API للمالك: list presets، preview، assign، rename، history؟
4. كيف نضمن أن تغيير preset لا يقطع StoryScene جارية؟ اقتراح (م): القصة الجارية
   تثبت `presetCode/version` عند claim، والتغيير يعمل من القصة التالية.

## 9. أثر القرار على الجولة A

نلغي خيارات A/B/C السابقة كاتجاهات مقبولة. الاتجاه الوحيد المعتمد هو مرجع (ع)
الأخير: 3D كبير الرأس وصغير الجسم. لا نبني bones على SVG المسطح السابق.

أول خطوة بصرية جديدة: Golden Sample للرجل الحالي بنفس الستايل، ثم Golden Sample
للمرأة، ويقبلهما (ع) قبل إنتاج بقية المكتبة.
