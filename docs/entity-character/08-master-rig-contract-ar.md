# (م) → (ز) والمصممة: عقد Master Rig للمراقب

هذا الملف **عقد تنفيذ** بين تصميم Rive وكود React. الأسماء أدناه ثابتة
وحساسة لحالة الأحرف؛ لا تُترجم ولا تتغير من طرف واحد.

## 1. نطاق النسخة الأولى

ملف Rive واحد قابل لإعادة الاستخدام لكل الموظفين، بمظهر mascot لطيف
ثنائي الأبعاد بعمق بصري قريب من النموذج المعتمد: رأس أكبر نسبياً، جسم كامل،
سترة الأماني الزرقاء فوق ملابس سوداء. اختلاف الموظف يدخل عبر طبقات المظهر،
ولا ننشئ State Machine أو ملف `.riv` جديداً لكل موظف.

المطلوب في النسخة الأولى: وقوف وتنفس، رمش، تتبع النظر، التفات رأس خفيف،
تلويح، تأشير إلى موضع تنبيه، كلام بصري، مشي، وتعبير حالة هادئ/إيجابي/تحذير/خطر.

## 2. أسماء الملف والبنية

- Artboard: `EmployeeObserver`
- State Machine: `ObserverSM`
- المقاس المنطقي: `720 × 1080` بنسبة `2:3`
- مركز الشخصية: `x=360`
- مستوى الأرض: `y=1010`
- Fit في التطبيق: `contain`
- Align: `bottomCenter`
- نقطة ارتكاز الجسم الرئيسية: منتصف الحوض.
- نقاط الذراع: مفصل الكتف، الساعد: المرفق، اليد: الرسغ.
- نقطة الرأس: قاعدة الرقبة، لا مركز الصورة.
- كل رسم يبقى داخل الـArtboard في أقصى وضعية تلويح/تأشير.

## 3. مدخلات `ObserverSM`

| الاسم | النوع | المجال/القيمة | المعنى |
|---|---|---|---|
| `lookX` | Number | `-1..1` | اتجاه العين/الرأس: يسار إلى يمين بصرياً |
| `lookY` | Number | `-1..1` | أعلى إلى أسفل بصرياً |
| `walkSpeed` | Number | `0..1` | صفر وقوف، وما فوقه دورة المشي |
| `talkLevel` | Number | `0..1` | مقدار فتح الفم؛ ليس تشغيل صوت |
| `mood` | Number | `0,1,2,3` | calm, positive, warning, critical |
| `reducedMotion` | Boolean | `true/false` | يوقف الحركات المستمرة غير الضرورية |
| `isVisible` | Boolean | `true/false` | يجمّد الحركة إذا الصفحة/الكيان مخفي |
| `blink` | Trigger | — | رمشة فورية واحدة |
| `wave` | Trigger | — | تلويحة واحدة ثم رجوع |
| `point` | Trigger | — | تأشير واحد ثم رجوع |
| `react` | Trigger | — | تفاعل لطيف عند الضغط |

قاعدة مهمة: اتجاه `lookX` بصري وليس RTL؛ `-1` دائماً يسار الشاشة و`1`
يمينها. كود الحركة في React يحول إحداثيات المؤشر إلى هذا المجال.

## 4. الحالات والانتقالات

- الحالة الأساسية `Idle`: تنفس خفيف وحركة جسم لا تتجاوز 2%.
- `Walking`: تدخل تدريجياً حين `walkSpeed > 0.05` وتخرج دون قفزة.
- `WaveOnce`, `PointOnce`, `ReactOnce`: طبقات one-shot فوق Idle/Walking،
  لا تمنع الرمش أو الكلام، وتعود تلقائياً.
- المزاج لا يستبدل الرسم: يغير الحاجبين والفم ووضع الرأس/الكتفين بانتقال
  `180–260ms`، دون فلاش أو اختفاء.
- `critical` واضح لكن غير مرعب: لا أحمر وامض ولا اهتزاز مستمر.
- `talkLevel` يقود 3–4 أشكال فم متدرجة؛ لا تعتمد المصممة lip-sync داخل الملف.
- الرمش Trigger من الخارج حتى يتحكم الكود بالتوقيت، ولا Timer عشوائي داخل Rive.
- عند `reducedMotion=true`: لا تنفس، لا sway، لا مشي حلقي بصري؛ تبقى الرمشة
  والتأشير/التفاعل القصير عند طلب المستخدم، مع انتقالات مختصرة.
- عند `isVisible=false`: تتوقف جميع الحركات المتكررة فوراً.

## 5. طبقات المظهر القابلة للتبديل

تُجمع كل منطقة في Group/Slot مستقل، ولا تُدمج بصورة نقطية واحدة:

`skin` · `faceBase` · `ears` · `hairBack` · `hairFront` · `brows` ·
`eyes` · `nose` · `mouth` · `beard` · `mustache` · `glasses` ·
`headwear` · `vest` · `shirt` · `pants` · `shoes` · `companyLogo`

والأطراف تبقى منفصلة للحركة:

`upperArmL/R` · `forearmL/R` · `handL/R` · `thighL/R` · `shinL/R` ·
`footL/R`.

إذا Data Binding/Keys يسمح بتبديل Images أو Groups بأسماء مستقرة نستخدمه.
إذا نسخة Rive لا توفر ذلك بصورة موثوقة، تُسلّم Variants داخل Artboard بنفس
الأسماء ولا تُخترع تسمية ثانية قبل الاتفاق مع (ز).

## 6. عقد الهوية البصرية

- السترة أزرق الأماني؛ اللون الأساسي يأتي من التطبيق/الـappearance profile.
- الشعار ملف vector رسمي مستقل، لا يُرسم من الذاكرة ولا يُشوّه.
- تحت السترة: قميص وبنطلون وحذاء أسود فقط.
- ملامح الموظف الأساسية محفوظة: شكل الوجه، لون البشرة، الشعر، اللحية/الشارب،
  النظارة والسمات الظاهرة. لا تغيير عمر/جنس/لون بشرة.
- الرأس أكبر من الواقعي لكن لا يتحول إلى طفل أو كاريكاتير ساخر.
- لا خلفية داخل ملف Rive؛ الخلفية ومساحة الحركة مسؤولية الواجهة.
- لا نصوص ولا فقاعات كلام داخل `.riv`؛ React يرسمها حتى تدعم RTL والوصولية.

## 7. مدخلات المظهر من النظام

الـappearance profile المقترح (يُخزن لاحقاً في `EmployeeCharacter.appearance`):

```json
{
  "version": 1,
  "skinTone": "#...",
  "hairColor": "#...",
  "eyeColor": "#...",
  "vestColor": "#...",
  "assetKeys": {
    "face": "...",
    "hairFront": "...",
    "hairBack": "...",
    "beard": "...",
    "mustache": "...",
    "glasses": "..."
  }
}
```

الألوان والـasset keys فقط داخل الملف؛ الاسم، التنبيه، الصوت، المكان، الصلاحيات
وحالة الموظف ليست جزءاً من Rive.

## 8. ما لا تفعله المصممة

- لا تضيف منطق أعمال أو رسائل أو مؤقتات عشوائية.
- لا تسجل صورة الموظف الأصلية داخل `.riv`.
- لا تعمل ثلاث شخصيات/صور منفصلة للمزاج.
- لا تحول الشخصية كلها إلى PNG واحد.
- لا تغير أسماء Artboard/State Machine/inputs/slots.
- لا تضيف خلفية، ظل بطاقة، أزرار، أو فقاعة كلام.
- لا تجعل حركة العين تتطلب تحريك الرأس كله.
- لا تستخدم مؤثرات ثقيلة قبل قياس الأداء على الجهاز الضعيف.

## 9. تسليم المصممة

1. `employee-observer-master.riv`
2. نسخة source قابلة للتعديل داخل حساب الشركة.
3. صورة preview للحالات الأربع.
4. صفحة قصيرة تسجل نسخة Rive وتاريخ التصدير وأي feature تجريبي مستعمل.
5. اختبار موظف واحد فقط أولاً؛ لا إنتاج بقية الموظفين قبل قبول الـSpike.

## 10. شروط قبول الـSpike

- يجد runtime حرفياً `EmployeeObserver` و`ObserverSM` وكل المدخلات المذكورة.
- تعمل `lookX/lookY` والعين مستقلة، والرأس يتبع بمدى أخف.
- تعمل triggers الأربعة عدة مرات بلا تعلق في حالة وسطية.
- الانتقال بين `Idle/Walking` وبين المزاجات بلا قفزة.
- `reducedMotion` و`isVisible` يوقفان الحركة المطلوبة.
- لا يقصّ أي طرف داخل الـArtboard.
- هوية السترة والملابس مطابقة، ووجه الموظف التجريبي مقبول من (ع).
- نسجل build size وFPS والذاكرة قبل/بعد؛ لا نعتمد الملف على الانطباع وحده.

## 11. تقسيم المسؤولية المقترح

- المصممة: الفن، layers، bones، weights، animations، State Machine، وتسليم `.riv`.
- (م): الاتجاه البصري، مراجعة المظهر والحركة وواجهة وجود المراقب وقابلية الاستخدام.
- (ز): schema/appearance، Rive runtime، `useEntityRig`، الأحداث والبيانات وfallback.
- (ع): قبول درجة مطابقة الوجه وشخصية المراقب وسلوك التنبيه.

## 12. نقطتان أحتاج تثبيتهما من (ز)

1. هل runtime المختار يدعم تبديل assets/keys من React بالإصدار الذي سنثبته،
   أم نعتمد image replacement عبر Data Binding؟ ثبّت الآلية واسم الحزمة قبل أن
   تبدأ المصممة ببناء Slots نهائياً.
2. هل حركة انتقال الكيان داخل الواجهة تبقى CSS/Framer حول canvas (اقتراحي)،
   بينما Rive مسؤول عن دورة المشي داخل الشخصية؟ هذا يمنع خلط إحداثيات الصفحة
   بإحداثيات الـArtboard.

إذا وافق (ز) على النقطتين، هذا العقد يصبح أساس `02-decision.md` ولا يبدأ دمج
الإنتاج قبل نجاح Spike موظف واحد.
