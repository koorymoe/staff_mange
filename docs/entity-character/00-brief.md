# الكيان — بناء الشخصية: ورقة النقاش

**الفرع**: `entity/design-talk` — للنقاش والاتفاق فقط. **ماكو تنفيذ هنا**،
وماكو دمج بـ`prod` قبل موافقة (ع).

**الأطراف**: **(ز)** المسؤول والمُقرِّر · **(م)** المنفّذ · **(ع)** صاحب النظام.

---

## ① السياق — شنو موجود اليوم

الكيان (`frontend/src/components/EntityCompanion.tsx`، ٣١٠ سطر) شغّال
ويرد بأرقام حقيقية من `GET /api/entity/briefing`:

- المزاج ثلاث حالات: `HAPPY` · `WATCHING` · `ANGRY` (يُشتق من ورق متأخر،
  مهام إضافية، حجوزات بلا تواصل، وخصم انضباط).
- الجسم **صورة PNG** (`<img>`, السطر ٢٧٣) تُختار بـ`moodImage()` (السطر ٢٩٣)
  من `calmUrl`/`happyUrl`/`angryUrl` — صور تُولَّد بالذكاء وتُخزَّن بالخادم.
- الحركة كلها **خارجية**: `entity-float`/`entity-alert` (CSS keyframes)،
  و`scaleX(facing)` يقلب الجسم كله ناحية الماوس (السطر ٢٧٠).
- بلا صورة مولَّدة ← يسقط لإيموجي `employee.attendanceIcon` (السطر ٢٧٩).

### ⚠️ العلّة الي دزّنا لهذا النقاش

(ع) شاف النتيجة وكال: **«هاي صورة، ماريد صورة — اريد شخصية كارتونية»**.
والصورة النقطية **ما ينحرك فيها بؤبؤ عين ولا حاجب ولا فم** — إحساس
«يراقبك» چان حيلة خارجية بس. المطلوب مفاصل حقيقية.

### ⚠️ وقيد عملي ثاني

توليد الصور بالذكاء **ما اشتغل ولا مرة** بالإنتاج: يحتاج `GEMINI_API_KEY`
+ `GEMINI_IMAGE_MODEL`، **٣ نداءات لكل موظف**، وسقف يومي ٣٠٠ نداء
مشترك مع المساعد. أي حل جديد لازم يشتغل **من أول ثانية لكل موظف**
بلا نداء خارجي.

**لا (ز) ولا (م) يقدر يفتح محرراً رسومياً.** الاثنين بالطرفية.

مقروءاً ومراجَعاً بـgit**.

## ③ السؤال المطروح للنقاش — طريقان، واحد ينختار

### الطريق (أ): شخصية **SVG** مرسومة بالكود

مسارات فيكتور بـ`<g>` مستقلة، تتحرك بـ`transform` محسوب من props.

- ➕ خفيفة جداً، تشتغل على أي جهاز، تنقرأ بـgit سطر-سطر، صفر مكتبات.
- ➕ التلوين لكل موظف تافه (`fill` من prop).
- ➖ الشكل **مسطّح** — أبعد عن الصورة الي دزّها (ع) (٣D لامعة).

### الطريق (ب): شخصية **٣D مبنية بالكود** بـBabylon.js

⚠️ **الاكتشاف الي غيّر النقاش**: `@babylonjs/core` **موجود أصلاً
بـ`frontend/package.json`** (مستعمل بمختبر المحاكاة) — يعني محرّك ٣D
كامل **بالحزمة أصلاً، صفر مكتبة جديدة**.

الشخصية تُبنى **إجرائياً** من أشكال أساسية (كرة للرأس، كبسولة للجذع،
أسطوانات للأطراف) + مواد + عظام بسيطة — كلها بالكود، بلا ملف نموذج
ولا Blender.

- ➕ أقرب بصرياً للصورة الي دزّها (ع): عمق، إضاءة، ظل، دوران حقيقي.
- ➕ تتبّع العين والرأس يصير حقيقياً بالفضاء (`lookAt`) مو حساب مسطّح.
- ➖ **أثقل**: canvas + حلقة رندر على كل صفحة يفتحها الموظف، وأجهزة
  الفنيين بالميدان ضعيفة. (⚠️ لازم يُقاس فعلياً، مو يُخمَّن.)
- ➖ شخصية بشرية إجرائية بلا رسّام **ممكن تطلع رديئة** — «روبوت مكعبات»
  أسوأ من SVG مسطّح نظيف.

## ⑤ العقد التقني — ثابت مهما ينختار الطريق

الشخصية **مكوّن عرض صافي**. كل القيم تجي من برّا حتى يبقى تبديل
المحرّك (SVG ↔ ٣D ↔ Rive مستقبلاً) **تبديل ملف واحد**:

```ts
export type EntityMood = 'HAPPY' | 'WATCHING' | 'ANGRY'

export interface EntityAvatarProps {
  mood: EntityMood
  lookX: number    // -1 يمين .. 0 كدام .. 1 يسار
  lookY: number    // -1 فوق .. 0 .. 1 جوه
  blink: number    // 0 عين مفتوحة .. 1 مغمضة
  talk: number     // 0 فم مسكّر .. 1 مفتوح
  breathe: number  // -1..1 موجة تنفّس
  skin: string; hair: string; vest: string
  className?: string
}
```

⚠️ **صفر** `useState`/`useEffect`/`setInterval`/`requestAnimationFrame`/
`Math.random()` داخل مكوّن الشخصية. الحلقة الحركية (`useEntityRig`)
مسؤولية (ز)، وحدة بس، تتوقف عند `document.hidden`، وتحترم
`prefers-reduced-motion`.

⚠️ **ألوان كل موظف** تُشتق حتمياً من `employee.id` (هاش ← لوحات جاهزة)
— بلا ترحيل قاعدة بيانات، وبلا نداء ذكاء، ونفس الموظف نفس الشكل بكل جهاز.

## ⑥ شروط القبول (تنطبق على أي طريق)

1. يبني بـ`npx tsc -b` و`eslint --max-warnings=0` و`npm run build`.
2. **البؤبؤ** يتحرك — مو قلب الجسم كله مثل اليوم.
3. الانتقال بين المزاجات **حركة**، مو استبدال صورة.
4. يشتغل لكل موظف **من أول ثانية** بلا أي نداء خارجي.
5. الصفحة مخفية ← الحركة تتوقف كلياً (بطارية الفني).
6. ما ينكسر ولا شي شغّال بالكيان: البريفينغ، الترحيب مرة بالجلسة،
   السحب وحفظ الموضع، اللوحة، المحادثة، ومستمع `open-manager-chat`.
