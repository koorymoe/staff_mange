## ② SSE لو WebSocket — ولا واحد منهما، وبدليل مقاس

**`WriteTimeout: 30 * time.Second`** — `cmd/api/main.go:55`.

SSE اتصال مفتوح يكتب لدقائق. مع هذا السقف الاتصال **ينقطع كل ٣٠
ثانية**، ويعيد الاتصال، وكل مرة استعلام جديد — يعني «القناة الفورية»
تطلع **أسوأ من الاستطلاع**، مو أحسن منه.

وحلّها مو سطر: خادم ثانٍ بإعدادات مختلفة، أو `http.ResponseController`
لكل مسار، **وحدّ اتصالات مفتوحة لكل موظف**. و**ماكو ولا مكتبة
websocket بالمشروع** — فحصته: صفر نتيجة لـ`gorilla` و`websocket`
و`event-stream` و`http.Flusher`.

**القرار: نبقى على الاستطلاع، ونسرّعه وقت القصة بس.**

الاستطلاع القائم: الإشعارات **٣٠ث** (`Layout.tsx:167`) · التنبيهات
الحيّة **٤٥ث** (`LiveAlerts.tsx:97`) · الكيان **٦٠ث**
(`EntityCompanion.tsx:30`).

الجديد: لمن يكون عند الموظف قصة `QUEUED`، الكيان **ينزل لـ٥ث** لحد ما
تخلص، وبعدها يرجع ٦٠ث. تأخير أقصاه خمس ثوانٍ — **والموظف أصلاً ما
يعرف متى انضغط الزر**، فما يحسّه.

وملاحظة: «الفوري» وهم بسيناريوك أصلاً — خطوتك ٦ تقول لو الموظف مو
متصل تبقى المهمة محفوظة. يعني **القاعدة هي مصدر الحقيقة**، وهذا
بالضبط الي يخلي SSE **تحسيناً مؤجَّلاً بعد القياس، لا شرطاً للبدء**.

## ③ أصغر schema — جدول واحد، صفر جداول أحداث جديدة

```sql
CREATE TABLE IF NOT EXISTS "StoryInstance" (
  id TEXT PRIMARY KEY,
  "eventId"   TEXT NOT NULL,           -- id الحدث الرسمي الموجود
  "eventKind" TEXT NOT NULL,           -- DISCIPLINE_POINT_DEDUCTED ...
  "storyType" TEXT NOT NULL,
  version     INT  NOT NULL DEFAULT 1,
  "senderEmployeeId"    TEXT REFERENCES "Employee"(id) ON DELETE SET NULL,
  "recipientEmployeeId" TEXT NOT NULL REFERENCES "Employee"(id) ON DELETE CASCADE,
  status      TEXT NOT NULL DEFAULT 'QUEUED',
  "currentStep" INT NOT NULL DEFAULT 0,      -- checkpoint
  payload     JSONB NOT NULL DEFAULT '{}',
  "deliveredAt" TIMESTAMPTZ, "seenAt" TIMESTAMPTZ,
  "openedAt"    TIMESTAMPTZ, "acknowledgedAt" TIMESTAMPTZ,
  "createdAt"   TIMESTAMPTZ NOT NULL DEFAULT now(),
  "expiresAt"   TIMESTAMPTZ
);

CREATE UNIQUE INDEX IF NOT EXISTS "story_event_recipient_unique"
  ON "StoryInstance" ("eventId", "recipientEmployeeId");

CREATE INDEX IF NOT EXISTS "story_pending_idx"
  ON "StoryInstance" ("recipientEmployeeId", "createdAt")
  WHERE status IN ('QUEUED','DELIVERED','PLAYING');
```

**ليش هذا أصغر من مقترحك:**

- **صفر جدول `DomainEvent`** — الحدث الرسمي موجود، ونخزن `id` مالته
  بس. جدول أحداث ثانٍ = **مصدرا حقيقة يفترقان**، ونفس العلّة الي
  نطاردها بكل جولة.
- **الـidempotency فهرس فريد مو عمود ولا كود** — `(eventId, recipient)`
  فريد يعني إعادة تشغيل أو نداء مكرر **ما تنشئ قصة ثانية**. نفس نمط
  `discipline_event_unique_penalty`.
- **أربع طوابع زمنية بدل حالة واحدة** — «وصل» و«انعرض» و«انفتح»
  و«أقرّ» أربع حقائق مختلفة، وأنت نفسك شدّيت عليها بالخطوة ١٠. عمود
  `status` واحد يبلع التفريق.
- **`currentStep` عدد صحيح** = الـcheckpoint. الاستئناف يبدي من
  الخطوة، ومحد يعيد الخصم لأن **الخصم منفصل أصلاً بجدوله**.

**وقاموس الأفعال الخمستعش يبقى بالكود** (خريطة Go/TS) **لا بالقاعدة** —
بيانات لا كود، نفس مبدأ `MonitorStageLabel` و`DesignCategoryLabels`.

## قرارا (ع) — رفعتلهما اعتراضين، وحسمهما

### (أ) شخصية المراقب نفسه تدخل شاشة الموظف

اعترضت: اليوم إشعار الخصم يوصل **بلا اسم منو خصم**، فدخول شخصيته
يكشف الهوية — تغيير سياسة مو تفصيل بصري.

**قراره: المراقب نفسه.** التمويه ينتهي، والموظف يعرف منو خصمه. وهذا
يطابق مبدأه القديم «الشفافية جزء من العقوبة» (تعليق `/api/discipline`).

**الأثر عليك وعلى المصممة**: **rig ثانٍ** بملابس/شارة مختلفة.

### (ب) الأحداث السبعة كلها تاخذ قصة جسدية

اعترضت: سبعة مصادر تعني عدة مشاهد باليوم الواحد، والموظف ينتجاهلها.

**قراره: السبعة كلها.** وعليه — **إدارة الطابور شرط بقاء مو تحسين**،
وتنبني من أول يوم:

1. **قصة جسدية وحدة تلعب بالوقت** (نصّك: «لا تعمل قصتان جسديتان معاً»)،
   والباقي **ينتظر بالطابور** لا ينلغي.
2. **تجميع**: ثلاث أوراق ناقصة بنفس الحجز ← **مشهد واحد** يذكر
   الثلاثة، مو ثلاث ركضات. الفهرس الفريد يمنع **التكرار**، والتجميع
   يمنع **الازدحام** — شغلتان مختلفتان.
3. **أولوية صريحة**: العقوبة/الأمان قبل الاحتفال — نفس ترتيب
   `EntityMoodPositive` الي انبنى وانرفع: **التحذير يسبق الفرح**.
4. **سقف يومي للمشاهد الجسدية**؛ بعده الباقي يتحول إشعاراً هادئاً
   بالصندوق **بلا ما يضيع**.

بلا هالأربعة الكيان يصير مزعجاً وينتجاهل — ووقتها **العقوبة نفسها
تفقد أثرها**.
