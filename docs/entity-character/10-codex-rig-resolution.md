# (م) → (ز): حسم تثبيتات الـRig الخمسة

## 1. المزاجات الأربعة — موافق

يثبت جدولك كما هو:

| قيمة Rive | عقد الخادم | المعنى |
|---|---|---|
| `0` | `HAPPY` | calm؛ نظيف بلا حدث إيجابي حديث |
| `1` | `POSITIVE` | فرح سببه حدث إيجابي حقيقي خلال 24 ساعة |
| `2` | `WATCHING` | warning؛ معلّقات بلا تأخير فعلي |
| `3` | `ANGRY` | critical؛ تأخير أو خصم فعلي |

التحويل النصي إلى الرقم مسؤولية الواجهة، ولا تستخدم `positive` بلا سبب. تنفيذ
`EntityMoodPositive` وشرطه بالخادم عليك مثل ما ثبتَّ.

## 2. الشبه ومكتبة الأجزاء — موافق بشرط قبول واضح

نفس الـSlots تخدم المسارين، ومكتبة الأجزاء تمنع توقف الـSpike على مزود الصور.
لكن أثبت هذا الفرق حتى ما يتحول الاحتياط إلى نتيجة نهائية بالخطأ:

- **Spike تقني:** مكتبة أجزاء مقبولة لاختبار الـRig والحركة والـruntime.
- **قبول المنتج النهائي:** غير مكتمل إلى أن ينجح مسار يحافظ على وجه الموظف
  بدرجة يقبلها (ع). مكتبة الأجزاء وحدها لا تحقق قرار «نسخة مطابقة للوجه».
- لا تُرسل صورة الموظف إلى أي مزود ولا يُختار مزود قبل موافقة (ع) على الخصوصية،
  الكلفة، مكان المعالجة، وسياسة الاحتفاظ.

## 3. تبديل الأصول — Spike قبل تثبيت العقد البرمجي

موافق: لا نخمن API ولا نضيف `@rive-app` إلى الإنتاج ضمن النقاش. أنت تختار
نسخة runtime محددة للـSpike وتثبت بالتجربة:

1. الوصول إلى `EmployeeObserver` و`ObserverSM`.
2. تغيير مدخلات الحالة كلها.
3. تبديل أصل تجريبي واحد من React دون إعادة إنشاء الـcanvas.
4. تنظيف instance/resources عند unmount وعدم نمو الذاكرة بعد 20 دورة mount.

إذا فشل تبديل الأصل، لا تغير المصممة أسماء الـSlots؛ نوثق النتيجة ونختار
Data Binding أو fallback بعد القياس.

## 4. حركة الصفحة — CSS مثبتة

موافق: Rive لدورة الأطراف، وCSS يحرك حاوية الـcanvas داخل الصفحة. لا
`framer-motion` ولا مكتبة حركة ثانية. السحب الحالي لا يُعاد اختراعه.

## 5. ميزانية الأداء قبل البناء

هذه **بوابات Spike أولية قابلة للتشديد بعد baseline**، وليست أرقاماً ندعي أنها
مقاسة الآن:

| البند | الهدف | حد الرفض الأولي |
|---|---:|---:|
| ملف `employee-observer-master.riv` | `≤ 750 KB` | `> 1.0 MB` |
| إجمالي نقل runtime (JS + WASM مضغوطاً) | `≤ 1.5 MB` | `> 2.0 MB` |
| FPS والكيان ظاهر على الجهاز الضعيف | median `≥ 55` | median `< 50` |
| Main-thread long tasks أثناء idle، عينة 30 ثانية | `0` فوق `50ms` | أكثر من `2` |
| instances متحركة آنياً | `1` | أكثر من `1` بلا قياس جديد |
| حركة عند hidden | `0` frames مستمرة | أي loop مستمر |

إذا حجم runtime الحقيقي يتجاوز السقف قبل ملفنا، نسجل الرقم ولا نزوره: يصير
قرار اعتماد منفصل أمام (ع)، ونقارن Rive بالـSVG fallback. التحميل lazy عند
ظهور الكيان؛ لا يدخل runtime في المسار الأولي لشاشة الدخول.

## 6. مكان النسخة والأرشفة

- مصدر المصممة، `.riv`، والـpreview: معرض التصاميم، تصنيف `OTHER`، بعنوان
  يتضمن `Employee Observer Master vN`.
- النسخة المعتمدة الوحيدة داخل الواجهة:
  `frontend/public/entity/employee-observer-master.riv`
- لا تُحفظ نسخة ثانية داخل `src`، ولا يُستبدل الملف بلا رفع source/preview
  المطابقين للمعرض وتسجيل رقم النسخة.
- التطبيق يقرأ مساراً ثابتاً؛ cache busting يكون بإصدار build أو query version
  مو بتغيير اسم العقد كل مرة.

## 7. أسماء الـSlots

قائمة أشكال واسعة قبل إثبات تبديل أصل واحد عملياً.
