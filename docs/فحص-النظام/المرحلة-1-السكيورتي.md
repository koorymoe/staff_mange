## A-01 · 🔴 عالي — مدير النظام يقدر ينزّل المالك أو يوقف حسابه

**وين:** `backend-go/internal/service/employee_service.go:139-156`
المسار `PUT /api/employees/{id}` (`cmd/api/main.go:637`) محروس بـ`requireAdmin` وبس،
و`requireAdmin = RequireRole(employeeRepo, notificationRepo, "ADMIN")`.

**شنو صاير:** الكود يمنع صح إن أحد *يمنح* دور المالك:

```go
if *req.Role == "OWNER" && employee.Role != "OWNER" {
    return errors.New("دور المالك محجوز لحساب واحد بس، ما ينمنح من الواجهة")
}
```

ويمنع تغيير بيانات الدخول والصورة على غير المالك (`employee_handler.go:107,118`).
**بس ماكو أي فحص إن الهدف نفسه مالك** عند تغيير الدور أو الحالة:

```
PUT /api/employees/<ownerId>   { "role": "TECHNICIAN" }
PUT /api/employees/<ownerId>   { "status": "SUSPENDED" }
```

`req.Status` ينكتب بلا أي شرط (`employee_service.go:139-140`).

**الأثر:** أي حساب `ADMIN` يشيل المالك من دوره أو يوقف حسابه بنداء واحد.
و`RequireAuth` يقرا الدور **طازجاً من القاعدة بكل طلب** — فالمفعول **فوري**،
بلا انتظار انتهاء التوكن. المالك ينقفل عنه: مراقبة النسخ الاحتياطية · فتح الحسابات المحظورة ·
فتح الحسابات الجديدة · مركز القيادة.

**ليش مهمة:** التعليق بـ`employee_handler.go:97-101` يشرح بالضبط إنه يسدّ باب
«مدير النظام يستولي على حساب المالك» عن طريق بيانات الدخول. الباب انسدّ —
بس الطريق الأقصر (نزّله بس) ضل مفتوح.

**الحل:** فحص واحد بأول `Update` — لو `employee.Role == "OWNER"` ودور المُنفِّذ مو `OWNER`،
ارفض تغيير `Role` و`Status`.

## A-02 · 🔴 عالي — وسم الملفات ما يخص لا موظفاً ولا ملفاً

**وين:** `internal/storage/token.go:26-30` · `internal/handler/file_handler.go:76-104` · `cmd/api/main.go:563`

```go
func NewFileToken(secret []byte) string {
    exp := time.Now().Add(fileTokenTTL).Unix()
    payload := strconv.FormatInt(exp, 10)
    return payload + "." + sign(secret, payload)   // ← وقت الانتهاء وبس
}
```

ماكو بالوسم لا رقم الموظف ولا مفتاح الملف. و`Serve` يتحقق من الوسم بس (سطر ٨٣) —
ماكو ولا فحص «هذا الموظف إله حق يشوف هذا الملف».

**الأثر:** أي موظف مسجّل — حتى بأوطى دور — يجيب وسماً من `GET /api/files/token`
ويقرا بيه **أي ملف بالنظام** ١٥ دقيقة: وثائق زبائن · وصولات · صور هويات.
والوسم يمشي بالـ`query string`، فينحفظ بسجلات الوصول وبتاريخ المتصفح وبترويسة `Referer`.

**ملاحظة إنصاف:** الحماية الفعلية هسه إن المفتاح عشوائي (`storage.NewKey` — ١٦ بايت).
وهذا يمنع *التخمين* فعلاً، مثل ما يقول التعليق بـ`main.go:557`. بس الخطر مو التخمين:
المفاتيح تنرجع بردود API كثيرة، فأي موظف يشوف سجلاً يشوف مفتاح ملفه.

**الحل:** وقّع `employeeID + "|" + key + "|" + exp` بدل `exp` لحدها،
وخلّي الواجهة تطلب وسماً لكل ملف (أو وسماً واحداً يشمل مفاتيح الصفحة).

## A-03 · 🟠 متوسط — سجل حركة الأدوات مفتوح لكل موظف

**وين:** `internal/handler/inventory_handler.go:207-214` · المسار `cmd/api/main.go:950` بـ`requireAuth` وبس.

```go
func (h *InventoryHandler) ToolEvents(w, r) {
    events, err := h.service.ListToolEvents(
        r.URL.Query().Get("toolId"),
        r.URL.Query().Get("employeeId"))   // ← بلا أي فحص
```

**الأثر:** أي موظف يقرا سجل حركة أدوات الشركة كلها — منو فقّد شنو، ومتى، ومنو سجّلها.

**ليش تستاهل انتباه:** **كل أخواتها بنفس الملف انصلّحن**، وبتعليقات تشرح العلّة:
- `ListPersonalTools` (١٠٨): «چان أي موظف يبدّل الرقم بالرابط ويقرا عدة أي زميل»
- `ListToolRequests` (٣٠٧): «كانت ترجع طلبات كل الكادر لأي موظف مسجّل دخول»

هاي وحدها انفلتت من نفس الجولة.

**الحل:** نفس نمط جيرانها: `if employeeID != self && !h.canSeeOthersTools(r) { employeeID = self }`

## A-04 · 🟠 متوسط — استعلامان لقاعدة البيانات بكل طلب مُوثَّق

**وين:** `internal/middleware/auth.go:64` ثم `internal/service/auth_service.go:200-217`

`RequireAuth` ينادي `StatusAndRoleByID` (استعلام ١)، وبعدها `SessionValid` ينادي `FindByID`
(استعلام ٢) — و`FindByID` يسحب **صف الموظف كامل**، وبيه تجزئة كلمة السر
وتجزئة باسورد مركز القيادة، مع إنه ما يحتاج غير عمود واحد: `sessionsInvalidatedAt`.

**الأثر:** كل طلب بالنظام = استعلامان، والثاني ثقيل بلا سبب. وسحب تجزئات كلمات السر
لذاكرة العملية بكل طلب مو ممارسة زينة حتى لو ما تنطبع.

**الحل:** استعلام واحد يرجّع `status, role, sessionsInvalidatedAt` سوة.

## A-05 · 🟠 متوسط — تعداد أسماء المستخدمين عبر فرق التوقيت

**وين:** `internal/service/auth_service.go:57-62`

```go
employee, err := s.employees.FindByUsername(username)
if err != nil || employee == nil || employee.Password == nil {
    _ = s.loginAudit.Record(username, nil, false, ip, userAgent)
    return nil, "", ErrInvalidCredentials    // ← رد فوري، بلا bcrypt
}
```

**الأثر:** يوزر مو موجود يرجع بميلي ثانية، ويوزر موجود يرجع بعد `bcrypt` (~٦٠-١٠٠ م.ث).
الفرق قابل للقياس، فالمهاجم يميّز الأسماء الصحيحة قبل ما يبدي يخمّن.
وتحديد المعدّل (٨ محاولات/دقيقة) يبطّئه بس ما يوقفه.

**الحل:** لو اليوزر مو موجود، قارن بتجزئة bcrypt وهمية ثابتة حته يتساوى الزمن.

## A-06 · 🔵 منخفض — عدّاد تحديد المعدّل ما ينكتب بمسار الرفض

**وين:** `internal/middleware/rate_limit.go:69-80`

```go
recent := attempts[ip][:0]          // ترشيح فوق نفس المصفوفة
for _, t := range attempts[ip] { if t.After(cutoff) { recent = append(recent, t) } }
if len(recent) >= maxAttempts {
    mu.Unlock(); writeError(...); return     // ← رجع بلا attempts[ip] = recent
}
attempts[ip] = append(recent, now)
```

الترشيح ينكتب فوق المصفوفة الأصلية، وبمسار الرفض ما ينحدّث طول الشريحة —
فتبقى بالطول القديم وبيها طوابع مكررة بالنهاية.

**الأثر:** محدود — العدّ ينتفخ داخل النافذة على عنوان محظور أصلاً، والمكررات تنتهي
بنفس وقت أصولها فما يطول الحظر. مو ثغرة، بس سلوك غلط.

**الحل:** `attempts[ip] = recent` قبل الرجوع.

## ✅ الي طلع نظيفاً — وتأكدت منه

- ماكو **حقن SQL** — ٨ حالات `Sprintf` بس، كلها `$N` وأسماء أعمدة ثابتة
- ماكو `ORDER BY` مبني من مدخلات المستخدم
- ماكو أي **سر مكتوب بالكود** — `config.go` كله من البيئة
- `JWT_SECRET` مفروض بالإقلاع، والسيرفر يرفض يشتغل بدونه (`main.go:27`)
- JWT يثبّت **`HS256`** صراحةً — ماكو `alg confusion` (`auth_service.go:225`)
- **bcrypt** بكل مكان — ماكو md5 ولا sha للكلمات
- `hmac.Equal` مقارنة ثابتة الزمن بالوسم
- **اجتياز المسار** (`../`) مقفول صح (`storage/local.go:37-44`)
- نوع الملف من **محتواه** مو من الترويسة + قائمة بيضاء
- **إبطال الجلسات** عند تغيير كلمة السر شغّال فعلاً
- **الدور يُقرأ طازجاً** من القاعدة بكل طلب مو من التوكن
- فصل `realm` (مركز القيادة) محروس **بالاتجاهين**
- `X-Forwarded-For` ما ينوثق إلا من بروكسي داخلي
- مهلات `http.Server` مضبوطة ضد slow-loris
- **CSP كامل وصارم** بـ`frontend/nginx.conf:53` + ترويسات الحماية بالطرفين
- رفع دور المالك ممنوع بالإنشاء وبالتعديل

## شجرة المسارات و IDOR

**كل مسار بالنظام انفحص.** أربعة وبس بلا حارس دخول، وكلها مقصودة:
`GET /api/health` · `GET /api/files/` (بوسم — شوف A-02) · ونموذجان عامان للتصميم بتحديد معدّل مستقل.
**ماكو ولا مسار إداري منفلت.**

**و IDOR:** ١٨٨ موضعاً ياخذ الهوية من سياق الجلسة (الصح) مقابل ١٠ من الرابط.
فحصت العشرة وحدة وحدة — سبعة عدهن فحص ملكية صريح وموثّق، واثنان محروسان بالدور،
والعاشر هو A-03.

## نقطة للنقاش مو علّة

`PasswordMinLength = 4` (`auth_service.go:243`) — قرار موثّق بالكود بسبب مقنع:
«الشروط الصعبة خلّت الموظفين ما يغيّرون سرهم أصلاً، والكل يبقى على الافتراضية».
الحماية الحقيقية من تعطيل الدخول بعد ٣ محاولات ومن تحديد المعدّل.
**مذكورة هنا حته تبقى قراراً واعياً، مو سهواً.**
