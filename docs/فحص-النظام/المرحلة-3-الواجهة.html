عالي F-01 · صفحة الصلاحيات: سباق يمنح موظفاً صلاحيات موظف ثاني

وين: frontend/src/pages/PermissionsPage.tsx:47-64

useEffect(() => {
  setPermsLoadFailed(false)
  api.getEmployeePermissions(selectedEmployeeId)
    .then((perms) => setEmployeePerms(perms.map((p) => p.name)))   // ← بلا حارس
    .catch(() => { setEmployeePerms([]); setPermsLoadFailed(true) })
}, [selectedEmployeeId])

السيناريو:

١ضغط على الموظف (أ) → ينطلق طلب (أ)
٢ضغط بسرعة على الموظف (ب) → ينطلق طلب (ب)
٣رد (ب) يوصل → الحالة = صلاحيات (ب) ✅
٤رد (أ) يوصل متأخراً → الحالة = صلاحيات (أ) ❌ والشاشة تعرض (ب)
٥permsLoadFailed = false — الطلبان نجحا. الزر شغّال وماكو تحذير
٦ضغط «حفظ» → setEmployeePermissions(ب, صلاحيات_أ)

والخادم يستبدل مو يضيف — الكاتب نفسه يوثّقها بالسطر ٥٩:

«ما انجلبت» مو «ماكو صلاحيات»: الحفظ يرسل القائمة كاملة والخادم يحذف كل صفوف الموظف ويعيد إدخال المؤشَّر بس.

الأثر: الموظف (ب) يفقد كل صلاحياته ويستلم صلاحيات (أ) — بهدوء، بلا خطأ ولا تحذير. ولو (أ) عنده صلاحيات أوسع، هاي ترقية صلاحيات بالغلط.

🔴 وليش مؤلمة: الكاتب شاف الخطر وحرس منه — permsLoadFailed وشريط تحذير أحمر وزر مقفول. بس الحارس يمسك مسار الفشل وبس، ومسار السباق يمرّ من جنبه لأن الطلبين نجحا.

الحل: ثلاث سطور — حارس alive بنفس النمط الموجود بـSalesBooking.tsx:131.

الأثر: المستخدم ما يفرّق بين «السيرفر واقع» و«ماكو شي هنا». والـ٧٧ أخبثهن: .catch(() => setX([])) تخلّي فشل الشبكة يطلع قائمة فاضية طبيعية، فالموظف يتخذ قراراً على «ماكو بيانات» وهي موجودة.

وهاي العائلة الي علّگت شاشة المراقب: .catch(() => {}) بلع فشل الحجز وترك الطبقة السودة معلّقة. ومترابطة مع B-03 بالباك إند (٢٦٣ ردّ 500 مقابل ٢٩ 404) — الخادم يرجّع خطأ مضلِّل والواجهة تبلعه بصمت. الطرفان يضيّعان نفس المعلومة.
