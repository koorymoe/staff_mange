## B-01 · 🔴 عالي — حجز محذوف لسه يزيد إنتاجية الموظف

**وين:** `backend-go/internal/repository/booking_repository.go` — **تسع دوال**:

```
CountCompletedForEmployeeMonth  (957)   CountCompletedForEmployeeRange
CountInHouseForEmployeeMonth    (969)   CountAssignedForEmployeeRange
CountAssignedForEmployeeMonth  (1004)   CountMaintenanceForEmployeeRange
CountMaintenanceForEmployeeMonth        CountFreeMaintenanceForEmployeeRange
CountFreeMaintenanceForEmployeeMonth
```

**شنو صاير:** النظام عنده تعريف **واحد** لـ«الحجز الي ينعدّ» يستثني المؤرشف والمطلوب حذفه:

```go
// booking_delete_filter.go:40
func BookingCountableSQL(qualifier string) string {
    return qualifier + `."archivedAt" IS NULL AND NOT ` + BookingDeletePendingSQL(qualifier)
}
```

و`List` — الي تعرضه الشاشات فعلاً — تطبّقه (`booking_repository.go:31-32`).
**والتسعة كلهن ما يطبّقنه.**

**الأثر:** كلهن يغذّن `service/employee_monthly_stats_service.go` — الإحصائية الشهرية للموظف.
فنفس المفهوم يطلع برقمين: الشاشة تعرض رقماً والإحصائية رقماً أكبر، والفرق حجوزات **محذوفة**.

**وأسوأ وحدة فيهن:** `CountCompletedForEmployeeMonth` تعدّ من `BookingVisitCrew`
**بلا أي ربط بجدول الحجز إطلاقاً** — فطلعات حجز محذوف تنعدّ كاملة بلا إمكانية استثناء:

```sql
SELECT COUNT(*) FROM "BookingVisitCrew" vc
JOIN "BookingVisit" v ON v.id = vc."visitId"
WHERE vc."employeeId" = $1 AND to_char(v."occurredAt", 'YYYY-MM') = $2
```

**🔴 وليش هاي بالذات مهمة:** هاي **نفس العلّة** الي صلّحها آخر كومِت `8e0fb03`،
ورسالته تقولها حرفياً:

> «لوحة الترتيب تعدّ `completedBookings` و`assignedBookings` **بلا** نطاق «الحجز الي ينعدّ» —
> يعني **حجز محذوف يزيد رصيد موظف**. والنقاط تنبني عليها تقييمات وقرارات».

انصلّحت **ثنتان** بـ`kpi_repository.go`، وبقت **تسعة** بنفس العائلة بملف ثاني.

**الحل:** إضافة `BookingCountableAndSQL("b")` لكل استعلام — نفس التعديل الي طبّقه الكومِت.
والأولى تحتاج ربطاً بجدول الحجز أول.

## B-02 · 🟠 متوسط — تغطية الاختبارات صفر تقريباً

| الحزمة | ملفات | تغطية |
|---|---|---|
| `repository` — كل الـSQL | ٩١ | **٠٫٠٪** |
| `database` — الترحيلات | ٧٩ | **٠٫٠٪** |
| `handler` | ٩٣ | ٠٫٨٪ |
| `model` | ٨٠ | ٢٫٦٪ |
| `service` | ٦٠ | ٤٫٢٪ |
| `middleware` | ٥ | ٤٫٨٪ |
| `safeguard` | ١ | **٩١٫٧٪** |

**الأثر:** ٦٦ ألف سطر مقابل ٢٫٢٥٩ سطر اختبار — ٣٫٤٪ بالحجم، وأقل بالتنفيذ.
و`repository` على **صفر** يعني كل استعلام SQL بالنظام — بما فيه حسابات الفواتير
وعدّادات الحجوزات — **غير مُختبَر إطلاقاً**.

**وهاي تفسّر الباقي:** B-01 فوق، وعلّة شاشة المراقب (C-01)، وعلّة `ToolEvents` (A-03) —
كلهن أصناف يمسكهن اختبار واحد. ماكو شبكة أمان تمسك «جولة إصلاح ما كملت».

**الحل العملي:** مو ٨٠٪ تغطية. اختبار واحد لكل قاعدة عدّ («حجز محذوف ما ينعدّ»)
يمسك عائلة كاملة. و`safeguard` بـ٩١٫٧٪ يثبت إن الفريق يعرف يكتب اختبارات لمن يقرر.

## B-03 · 🟠 متوسط — «مو موجود» يطلع ٥٠٠ بكل النظام

**الأرقام:** **٢٦٣** ردّ `500` مقابل **٢٩** ردّ `404` بكل طبقة `handler`.
و**١٨٦** دالة مستودع تجيب صفاً بـ`WHERE` بلا معالجة `sql.ErrNoRows`.

مثال — `repository/complaint_repository.go:149` يرجّع `err` خاماً:
```go
func (r *ComplaintRepository) Find(id string) (*model.Complaint, error) {
    var c model.Complaint
    if err := r.db.Get(&c, `SELECT * FROM "Complaint" WHERE id = $1`, id); err != nil {
        return nil, err      // ← ErrNoRows يطلع ٥٠٠
    }
```

**الأثر:** سجل مو موجود → الخادم يقول «عطل بالسيرفر». والواجهة تبلع الـ٥٠٠
بـ`.catch()` وتترك المستخدم بشاشة معلّقة بلا رسالة مفهومة —
**وهاي بالضبط عائلة العلّة الي علّگت شاشة المراقب (C-01)**.

**والعكس موجود بعد:** `booking_repository.go:1355` (`Postpone`) يبلع **أي** خطأ
قاعدة بيانات ويسمّيه «الحجز مو موجود» — فالعطل الحقيقي ينخبّي وراء رسالة مطمئنة.

## B-04 · 🟠 متوسط — استعلامات N+1 بثمانية مستودعات

**النمط:** `for i := range rows { r.hydrate(&rows[i]) }` و`hydrate` جوّاها نداءات `db.Get`.

```
complaint · leader_invoice · performance_review · quality_follow_up
service_manager · staff_request · team_inventory_check · work_report
```

**مثال محسوب:** `ComplaintRepository.hydrate` (سطر ٢٨) يسوي أربعة استعلامات لكل صف —
الزبون · الحجز · منو أنشأها · منو مُسندة له. فقائمة بـ١٠٠ شكوى = **٤٠١ استعلام** بدل ٢-٣.

**والحل موجود بالمستودع نفسه:** `leader_invoice_repository.go:417` عنده `hydrateAll` —
نسخة مجمّعة تجيب الكل بـ`ANY($1)`. النمط الصحيح مكتوب، بس ما انطبّق بكل مكان
(ونفس الملف عنده الاثنان).

## B-05 · 🔵 منخفض — خطر كامن: `::date` خام على عمود `TIMESTAMP`

**وين:** `repository/gps_repository.go` أسطر ٦٢٥ · ٦٤١ · ٧١٦ · ٧٨٦ · ٧٩٤ · ٧٩٥ · ٨٠١

`subscriptionEnd` نوعه `TIMESTAMP` (`schema_base.go:304`)، وينقارن بـ`::date` الخام
مقابل `baghdad_today()` — خلط بين تاريخ غرينتش وتاريخ بغداد.

**وصحيح اليوم:** تأكدت — `parseDate` (`cmd/importgps/main.go:68`) يفسّر `"2006-01-02"`
فيخزّن منتصف الليل دائماً، ومنتصف الليل + ٣ ساعات = نفس اليوم. **ماكو خطأ حالياً.**

**بس:** أول قيمة تنكتب بوقت (منتقي تاريخ ووقت، أو `now()`) → انتهاء الاشتراك
ينزاح **يوماً كاملاً** لأي قيمة بين ٢١:٠٠ و٢٤:٠٠ عالمي. وهذا بالضبط الصنف الي
انكتب `schema_baghdad_date.go` لإلغائه — وهاي السبعة انفلتن من تلك الجولة.

## ✅ الي طلع نظيفاً — وقسته مو خمّنته

- **ماكو ولا قسمة على صفر** — فحصت ١٣ موضع قسمة عشرية، كلهن محروسات بشرط صريح
  (`vehicle_service` ١٤٣/٤٢٢/٥٢٢ · `ai_metrics` ٧٧/١٠٨ · `job_duration` ٧٢/٨٠/٨١ ·
  `smart_kpi` ٩٦/١٢٥ · `mission` ٢٧٤/٢٧٨ · `project_service` ١٧٩ · `vehicle_repo` ٤٧٠)
- **تقريب الفواتير آمن** — شغّلت **٢٦٠٠ تركيبة أسعار واقعية** على
  `math.Ceil(sum/1000)*1000` بمضاعفات الارتفاع غير الدقيقة ثنائياً (١٫١٥ · ١٫٣ · ١٫٧):
  **صفر انحراف** عن الحساب الصحيح
- المعاملات سليمة — كل `Beginx` عنده `Rollback`، و`return tx.Commit()` يرجّع الخطأ فعلاً
- الترحيلات: كل نسخة بمعاملة مستقلة وتقف بأول فشل (`migrate.go:44-58`)
- **توقيت بغداد محلول صح بالقاعدة** — `baghdad_date()` / `baghdad_today()` بـ٥٧ موضع،
  وعلّة «شغل الساعة ١ فجراً ينحسب على اليوم الي فات» موثّقة ومحلولة
- الخيوط الخلفية محميّة بـ`safeguard.Loop` — انهيار كنسة ما يسقّط السيرفر
- `go build` · `go vet` · `go test -race` — كلها تمر نظيفة
- التحقق من المدخلات منضبط — ١٩٨ من ٢٠٦ نداء `DecodeJSON` تفحص الخطأ صراحة،
  والاستثناء الوحيد (`booking_handler.go:346`) محروس بتحقق بعده
- حسابات الفواتير **مرجوعة حرفياً للشيت** بتعليقات تشرح كل صيغة (G58 · K · M · P · R59)

## 🔴 الخيط الي يربط كلشي

B-01 و B-03 و B-04، وعلّة شاشة المراقب (C-01)، وعلّة `ToolEvents` (A-03) —
**كلهن نفس القصة**: التصميم صحيح ومفكَّر فيه، والقاعدة معرَّفة بمكان واحد،
والإصلاح مكتوب وموثَّق — **بس ما انطبّق على كل المواضع**.

| الي انبنى صح | الي انفلت |
|---|---|
| تعريف «الحجز الي ينعدّ» بملف واحد | ٩ عدّادات ما تناديه |
| `hydrateAll` المجمّعة مكتوبة | ٨ مستودعات يستعملون الفردية |
| حارس الملكية بثلاث دوال بملف المخزون | رابعة انفلتت |
| آخر كومِت صلّح عدّادين | ٩ بنفس العائلة بملف ثاني |
| `baghdad_date()` بـ٥٧ موضع | ٧ مواضع `::date` خام |

وهذا **مو ضعف بالمهارة — ضعف بالشبكة**. ماكو اختبار يمسك «الجولة ما كملت»،
و`repository` على **صفر تغطية**. فكل إصلاح يعتمد على إن الي يسويه يتذكّر كل المواضع —
وهذا ما ينجح دائماً، ولا عند أي أحد.
